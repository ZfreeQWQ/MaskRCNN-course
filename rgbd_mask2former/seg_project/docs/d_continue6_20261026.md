# D 继续训练与 GPU 调度

依据：现有最佳 D 权重来自 6 epoch 的末尾；第一轮完整验证证明增加推理分辨率有效。为尽快测试更长训练的价值，从该权重继续优化，同时完成推理对照。

实验目录：`/private/rgzndzy/seg_project/experiments/mask2former/d_continue6_20261026`。

- 起点：原 `d_screen/best_segm_APs.pth`。仅加载模型权重，重建 AdamW；这是低学习率重新开始优化，不是从头 12 epoch 对照。
- 增加 6 epoch：10,824 次更新，每批 8 张，共 86,592 次训练图片曝光。
- 学习率 3e-5，backbone 乘 0.1；100 步从 0.1 倍预热，8,659 / 10,066 步衰减。
- 保留 D 原架构、原 matcher/loss、1024 训练裁剪和全部数据增强；不启用已有 S 或 DSH 模块。
- 完整验证分辨率为 1536；原 D 的该尺度 legacy 对照 APs=0.500807164，mask-first 对照 APs=0.500942352。
- 每 902 步保存恢复 checkpoint，每 1,804 步完整验证一次，按 segm/APs 选最佳。原最佳 D 权重保留，不能仅因新模型训练结束就替换原结果。

双卡训练检查已完成 30 步，损失有限，退出码为 0，峰值显存 22,574 MiB/卡。检查结果位于独立目录 `d_continue6_smoke_20261026`，不参与模型选择。

当前调度：GPU 0、1 用于第一轮验证与 test；GPU 2、3 用于继续训练，每卡 4 张图，全局 batch=8。`tools/run_continue_training.py` 在第一轮提交全部导出完成且 GPU 0、1 空闲后，等待下一个完整 checkpoint，再停止它自己启动的双卡 torchrun 并以 4 卡恢复（每卡 2 张图，全局 batch 仍为 8）。恢复优化器、scheduler 和 iteration；dataloader 顺序不承诺逐位一致，保存与停止间的少量步骤会重放。日志和退出原因分别记录。

状态文件是 `manager_state.json`，其中包含 manager / torchrun PID、GPU 列表、attempt 和状态。训练日志为 `attempt1.log`、扩展后为 `attempt2.log`；`metrics.json` 逐行记录训练和验证指标。`gpu_expansion.json` 记录扩展所用 checkpoint。由于定期 checkpoint 在 EvalHook 之前保存，训练入口增加了仅在这类扩卡恢复时启用的补评估检查：如果刚好在完整验证节点恢复，且该次验证尚未完成，会先完成验证及最佳权重选择，再继续优化。普通训练和普通恢复的行为不变。5 项恢复判断测试通过。

从项目根目录启动：

```sh
./seg_project/run.sh python -u seg_project/tools/run_continue_training.py
```

已有 manager 或 checkpoint 时拒绝重复启动。异常时先检查 manager 与 torchrun 是否仍存活、最近 checkpoint 和日志，不重复启动同目录任务。所有产物保存在 `/private`；复用现有 PyTorch/CoreX，未修改系统环境。
