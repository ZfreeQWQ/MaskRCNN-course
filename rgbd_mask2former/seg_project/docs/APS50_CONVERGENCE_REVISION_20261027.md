# 充分训练与收敛判断修订（2026-10-27）

用户指出只训练2 epoch可能低估新方法。该问题成立：原先只有2 epoch筛选和最后选优，没有落实充分训练阶段。
本修订替代原方案中“所有实验在2 epoch结束并直接选模”的安排。旧结果保留为中间检查点，不据此宣布方法无效。

## 为什么需要改

原配方每组3608步，学习率在约1.6/1.86 epoch衰减，第2 epoch末已到1e-7。
新裁剪改变了输入尺度和上下文分布，追加局部损失改变了优化目标；从成熟权重开始也不能保证两轮就适应。
仅延长MAX_ITER而沿用末端极低LR，仍可能几乎没有有效更新；单看训练loss或两次val持平不能证明收敛。

本机现有Detectron2的LRMultiplier仅在state_dict中保存base_lrs与last_epoch，新构造的日程决定后续LR。
对应[官方源码](https://detectron2.readthedocs.io/en/latest/_modules/detectron2/solver/lr_scheduler.html)已核对。
本轮复用已有的优化器恢复检查和100步过渡预热，不安装或升级任何底层环境。

## 已部署的训练安排

| 阶段 | 预算 | 说明 |
|---|---|---|
| 所有四组 | 至少累计6 epoch | 同一父权重、相同2 epoch初始阶段，再保留各自完整状态追加4 epoch |
| 最佳改进组与对照组 | 至少累计12 epoch | 从各自6 epoch最终完整状态继续，保持相同训练预算 |
| 验证曲线仍改善 | 继续至18，再检查是否到24 epoch | 同预算对照同步延长；24是明确预算上限，不等于收敛 |

“累计”只计算本轮从原最优模型出发的额外训练，不包含父模型历史训练。
先让当前裁剪组正常完成2 epoch与完整验证，再进行四卡续训冒烟，然后优先把裁剪组训练到6 epoch。
后续为局部监督2→6、组合2→6、对照2→6，最后选择最佳改进组与对照做12/18/24阶段。
每组先前的2 epoch学习率历史相同，因此这是统一的“2+4”方案；不将其称为从头采用6 epoch日程的实验。

续训保留模型、AdamW一/二阶矩与全局iteration，重新建立更长的学习率日程。
每个新增阶段的80%/93%进度处衰减，基础LR=1e-5、骨干0.1倍、前100个续训更新平滑预热。
已训练的频率模块和label embedding仍使用成熟模块的LR规则。
新入口通过MRO保留focus mapper与局部损失，避免恢复训练时误回到原mapper。
加载器worker RNG顺序不保证逐位续接，不能声称数据顺序与不中断训练完全一致。

每epoch完整val 2584图，1536输入、原图mask-first推理保持一致；每902步保存断点。
始终保留历史最佳权重及其完整预测，续训若下降不会覆盖更好的父阶段结果。
每个阶段独立重算最佳预测的COCO分数与极小/低填充率召回切片。

## 停止判断

第一次判断不早于累计12 epoch。使用完整val APs（0–100尺度）：

1. 最近3次完整val相对更早历史最好值，未获得至少0.2点改善；
2. 当前阶段已到衰减后的低LR（≤1e-6）；
3. 两项同时满足，记录为“观察到验证平台”。若仍有改善，继续下一阶段。

这是一条可执行的经验停止规则，不是全局收敛证明。不能因最后一次回落而忽略前两轮出现的新最好分数。
到24 epoch若仍未满足平台规则，会明确记录`24_epoch_cap_reached_without_plateau`，不宣称已收敛或目标达成。
完整val选模仍以APs优先，整体AP下降超过父模型0.3点的候选不直接推荐。
只有优于父模型APs至少0.2点的候选才生成新的test CSV，隐藏test是否达到50必须另经Kaggle确认。
