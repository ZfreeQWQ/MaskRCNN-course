## 1. 任务目标与已知条件

PDF 的要求是：在统一 RGB-D 数据集上完成实例的分类、定位和像素级分割；以小目标掩码 AP（`APS`）为主指标；同时报告整体 `Mask AP`、模型大小和推理速度；完成 RGB 与深度信息读取、融合，并至少做一项针对小目标的改进；提交掩码 JSON、检测框 CSV、代码、报告和可视化案例。

当前数据集 `/private/rgzndzy/blender` 的实际情况：

| split | 图像 | 标注 | 场景范围 | 备注 |
|---|---:|---:|---|---|
| train | 14,432 | 448,469 个实例 | `0200000`–`0201959` | 1,804 个 COCO `json.gz` 分片 |
| val | 2,584 | 73,421 个实例 | `0201960`–`0202309` | 323 个 COCO `json.gz` 分片 |
| test | 2,112 | 无可用公开标注 | `0202310`–`0202619` | 只用于最终推理 |

图像和深度图都是 `1024×1024`；深度图是 `uint16` PNG，必须使用每张图的 `depth_scale_m` 转成米，并把 `depth_invalid_code`（通常为 0）作为无效深度处理。COCO 标注只有一个类别 `component`（`category_id=1`），但每个实例保留了 `semantic_type`，可用于误检和小目标分析。训练集约有 31 个实例/图，验证集约有 28 个实例/图，实例最多约 96 个/图，场景密度和遮挡是主要难点。

## 2. 总体实验路线

实验必须固定数据划分、随机种子、评价脚本和推理后处理，所有改动都通过验证集对比。建议按以下顺序推进：

1. 环境和数据完整性检查。
2. 运行 RGB-only Mask R-CNN 基线，确认 Detectron2、COCO 评估和提交格式都打通。
3. 加入深度，得到 RGB-D 基线并做消融。
4. 针对小目标完成一项主改进，优先选择高分辨率特征/小目标 anchors，必要时再加入深度门控融合。
5. 做消融、错误分析、速度和模型大小测试。
6. 只用最终模型推理 test，生成掩码 JSON 和检测框 CSV，整理报告和 Demo。

建议的实验编号：

| 编号 | 输入/方法 | 目的 |
|---|---|---|
| B0 | RGB + 标准 Mask R-CNN R50-FPN | 论文式基线，确认框架和评价链路 |
| B1 | RGB + 深度早期/后期融合，其他设置同 B0 | 衡量深度信息本身的收益 |
| M1 | B1 + 小目标 anchors、P2 高分辨率和更高 mask 分辨率 | 主改进，目标是提升 APS |
| M2 | M1 + 深度门控/注意力融合或轻量 PointRend | 可选第二改进，控制额外计算量 |
| A1 | M1 去掉深度 | 深度消融 |
| A2 | M1 去掉小目标改动 | 小目标改动消融 |

每个实验都保存配置、代码版本、随机种子、训练日志、最佳权重、验证集预测和指标 JSON，禁止只保留最终分数。

## 4. Mask R-CNN 基线实施

### 4.1 B0：RGB-only

使用 Detectron2 的 `Mask R-CNN R50-FPN`，COCO 预训练权重（若本地已有则使用；没有时记录为随机初始化或按允许的模型权重来源处理）。类别数设为 1。保持验证集固定，先用短跑验证链路，再进行完整训练。

首轮建议配置：

- 输入：RGB，保持长边不缩小，`MIN_SIZE_TRAIN` 在 `896/1024` 做小范围比较，`MAX_SIZE_TRAIN=1024`；验证固定为 1024。
- 每卡 batch size：从 1 开始；1024 分辨率下不要为了增大 batch 强行占满显存。
- 优化器：SGD，初始学习率按总 batch 线性缩放；若总 batch=4，先用 `0.01` 左右并用 200–500 iteration smoke test 验证稳定性。
- 训练长度：先 3k–5k iter 快速验证，再正式跑 1x/2x 两档（最终以验证集 APS 早停或选择最佳 checkpoint）。
- 增强：水平翻转、有限尺度抖动；先不加入会改变深度几何含义的随意增强。
- RPN/ROI：沿用官方 Mask R-CNN 设置，作为可复现基线。

Detectron2 原生 COCO evaluator 应输出 `bbox` 和 `segm` 的 `AP/AP50/AP75/APs/APm/APl`。由于主指标是掩码 APS，报告中必须以 `segm/APs` 为第一主表格指标，不能只报告 bbox mAP。

### 4.2 B1：RGB-D 基线

深度预处理：

```python
depth_m = depth_uint16.astype(np.float32) * image_info["depth_scale_m"]
valid = depth_uint16 != image_info.get("depth_invalid_code", 0)
depth_m[~valid] = 0
depth_norm = clip((depth_m - p1) / (p99 - p1), 0, 1)
```

`p1/p99` 只能从训练图像统计或按图像计算，必须在 train/val 使用同一约定；同时保留 `valid` 掩码，避免把无效深度误当成真实近距离。先实现最小 4 通道 RGB+D 输入：复制/修改 backbone stem 的第一层，RGB 权重按预训练值初始化，深度通道用 RGB 权重均值或零均值小权重初始化。若国产后端对修改后的算子支持不稳定，改用后期融合：增加轻量深度 encoder，在 FPN 的 P2–P5 用 `1×1 conv + gated addition/concat` 与 RGB 特征融合，Mask R-CNN 的 RPN、ROI heads 保持不变。

B1 必须和 B0 使用相同训练步数、增强、阈值和评估脚本，才能说明深度是否有效。记录深度无效比例、深度范围和可视化样例。

## 5. 针对小目标的算法优化

### 5.1 推荐主改进：高分辨率 FPN + 小目标 anchors

数据中的实例面积下四分位数约为 1,821 px²，存在大量小目标，标准 COCO anchors 对它们偏大。因此 M1 采用以下组合，并逐项做消融：

1. 保留/强化 FPN 的 P2 高分辨率路径；
2. 将 RPN anchor sizes 从默认起点向小尺度移动，例如 `[8, 16, 32, 64, 128]`，aspect ratios 先保持 `[0.5, 1.0, 2.0]`；
3. 提高 RPN 对小框的保留数量，检查训练和推理显存；
4. ROI mask head 的输入分辨率从 14 提高到 28，或仅对小 ROI 使用更高分辨率；
5. 训练尺度抖动覆盖 768–1024，避免所有目标在下采样后只剩很少像素。

每一步都要回答“APS 是否提升、整体 AP 是否下降、速度和显存代价是多少”。如果高分辨率全图导致显存或速度不可接受，采用 2×2 重叠裁剪训练/推理：裁剪时同步裁剪 polygon/RLE mask，边界实例按可见区域重新计算，推理后用 bbox/mask IoU 做合并。裁剪方案必须单独报告推理时间。

### 5.2 可选增强：深度门控或边界细化

在 M1 稳定后只选择一个附加方向：

- 深度门控：由深度特征产生 `[0,1]` gate，按空间位置调节 RGB FPN，期望利用前景/背景深度差异减少小目标误检；
- 轻量 PointRend/边界 refinement：只对高置信度、小面积 ROI 细化 mask，改善粘连和边界偏差。

不要同时堆叠多个难以归因的模块。最终报告至少包含 B0、B1、M1 以及去掉主改进的消融结果。

### 5.3 增强与后处理

使用水平翻转、有限颜色扰动、深度随机失效/噪声增强 RGB-D 鲁棒性；不要对深度做不符合几何意义的颜色增强。验证集固定阈值，阈值只根据验证集选择。测试推理使用同一阈值，可另做水平翻转 TTA 作为独立实验；若采用 TTA，必须计入推理时间并说明提交的是哪个版本。

## 6. 四张国产卡的使用方案

### 6.1 推荐策略：先并行试验，最终四卡同步训练

四卡不是简单地“每卡训练同一个模型但不通信”。推荐分两个阶段：

**开发和消融阶段：四卡各跑一个独立实验。**

- GPU0：B0 RGB-only；
- GPU1：B1 RGB-D；
- GPU2：M1 小目标 anchors/P2；
- GPU3：数据检查、短跑或另一组超参数（也可跑 M1 的第二随机种子）。

每个进程绑定一张卡、使用不同 `OUTPUT_DIR` 和固定 seed。这样能最大化实验吞吐，适合比较结构、学习率和输入尺度；各实验之间没有梯度同步。

**最终模型训练：四卡 DDP 同步。**

选定结构后，用一进程一卡的 DistributedDataParallel 训练同一个模型。先用 2–5 分钟 smoke test 验证国产后端的通信、梯度同步、checkpoint 和 evaluator，再正式运行：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 python /private/rgzndzy/detectron2/tools/train_net.py \
  --num-gpus 4 --config-file configs/m1_rgbd.yaml
```

如果仓库脚本或国产后端要求 `torchrun`，改用对应的 `torchrun --nproc_per_node=4` 入口；以实际后端支持为准。DDP 时：

- 每卡 batch=1 时全局 batch=4；学习率按实际全局 batch 调整；
- 只让 rank 0 写日志、评估和 checkpoint，避免文件竞争；
- 使用 DistributedSampler，确保每个 epoch 不重复取样；
- 每卡 32GB 先从 1024 分辨率 batch=1 开始，必要时用梯度累积；
- 比较单卡和四卡的 loss、吞吐、APS，确认没有通信导致的异常。

### 6.2 如果 DDP 不可用

若国产运行时的 NCCL/通信后端或 Detectron2 分布式算子不能稳定工作，采用四卡独立实验，不把四份未同步权重当成一个训练结果。最终可以：

- 用四卡同时跑四组可复现实验/随机种子；
- 用一张卡加载最佳模型做统一验证；
- 最终 test 推理按 image_id 分成四份，每卡输出独立 JSON，CPU 端按 image_id 合并；
- 只有在验证集证明有效时才做多模型 ensemble，并报告额外速度和模型大小。

这比为了“用满四卡”引入不稳定的跨卡通信更可靠。

## 7. 评估、记录与报告内容

### 7.1 必报指标

验证集主表至少包含：`segm/APs`、`segm/AP`、`segm/AP50`、`segm/AP75`、`segm/APm`、`segm/APl`，同时报告 bbox AP 作为辅助。每个实验记录：最佳 checkpoint iteration、参数量、权重文件大小、单张图平均延迟、吞吐 FPS、峰值显存和是否使用 TTA/裁剪。

速度测试固定 1024×1024 输入，预热 20–50 张后再测至少 200 张；分开报告数据读取时间和纯模型时间，并按实际国产卡后端做同步计时。模型大小同时报告参数量和 checkpoint MB。

### 7.2 小目标错误分析

从验证集按 COCO area 分组抽取：漏分割、误分割、边界不准、相邻实例粘连各 10–20 个案例，展示 RGB、深度、真实 mask、B0 预测、M1 预测。对每类错误写出原因假设，例如目标像素过少、深度无效、遮挡、相似背景或 anchor 不匹配，并用消融结果支持结论。

### 7.3 提交和 Demo

最终只读取 test RGB-D，按 `image_id` 生成：

1. COCO results 掩码 JSON：`image_id`、`category_id=1`、`bbox`、`score`、compressed RLE `segmentation`；
2. 2,112 行检测框 CSV：每行 `image_id,PredictionString`，无检测为空；
3. Demo：输入一张 RGB-D，展示 RGB、深度、真实 mask（仅 train/val）、B0 和最终模型预测。测试图片只展示预测，不展示任何测试标注。

提交前校验 image_id 数量、RLE 可解码、bbox 与 mask 外接框一致、无 NaN/负宽高、CSV 行数为 2,112。不要使用 test 标注做任何阈值或模型选择。
