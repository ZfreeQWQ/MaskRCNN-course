# RGB-D 元器件实例分割：第二轮算法与四卡实验计划

日期：2026-10-18。本文基于作业 PDF、数据说明、四组正式 1x 结果、训练源码、原始 train/val 标注及已有最佳验证预测制定。新增检查只在 CPU 上分析已有数据；未启动训练，未解除 `outputs/user_training_hold.json`，未改动原配置、权重和环境。

## 1. 决策

主路线保留 Mask R-CNN R50-FPN，优先解决 **跨型号泛化、可见区域稀疏的实例掩码、深度信息利用不足**。下一轮以四卡 DDP 的逐步验证为主，先缩短获得一个有效结论的等待时间；进入独立消融时再使用 2+2 或单卡并行。不能在未测吞吐前宣称四卡一定更快，也不建议直接启动原定 M1 2x 与三个全预算组件消融。

当前证据支持“原改动收益有限，需要重新定位”，不能据此把深度判为无用，或断言更大模型一定有效。正式比较仍以完整 val 的 Mask APs 为主，并报告整体 AP、速度与大小。

## 2. 作业的硬要求与此前计划的区别

`图像分割.pdf` 要求：实例分类/定位/分割；读取并融合 RGB-D；至少一项小目标算法改进；主指标 APs；整体 Mask AP、大小、速度；改进前后比较及漏分割、误分割、边界案例；RGB-D Demo。数据 README 还要求固定 train/val、test 仅推理、JSON 掩码及 CSV 检测框两类提交。

PDF **没有强制** 所有模型跑 1x/2x、三个旧组件都做 leave-one-out、指定 Mask2Former、每类必须凑足固定数量案例。这些是旧执行计划的设计，改变研究方向后应围绕新方法重建必要对照，不把旧计划的全部算力预算视为作业硬要求。正式输出类别始终只有 `component`，27/13 种 `semantic_type` 用于诊断/采样，不改成 27 类检测。

## 3. 已核实的结果与新证据

### 3.1 上轮表现

四组均为同源 COCO 预训练、单卡 batch=1、10 epoch、完整 val 2,584 图、每组一个 seed。以下 AP 为 0–100 标度，每行来自同一个 APs 最佳 checkpoint。

| 实验 | 输入与变化 | Mask APs | Mask AP | 模型 ms/图 |
|---|---|---:|---:|---:|
| B0 | RGB 标准基线 | 26.75 | 55.61 | 85.93 |
| B1 | 四通道早期融合 | 26.26 | 55.53 | 87.25 |
| M1 | B1 + 小 anchors / 更多 proposals / mask pool 28 | 27.52 | 54.92 | 136.08 |
| A1 | M1 去深度 | 27.98 | 55.56 | 135.31 |

深度两组配对的 APs 均约下降 0.5 点；小目标组合约提升 1.2 点，模型时间增加约 56%。单 seed 的小差异还没有排除随机波动。P2 原本存在，不能当作新增算法。

### 3.2 数据的关键特征

本次脚本重新读取 train/val 原始合并标注。small 按 COCO 的 `mask area <= 1024` 统计，为 train 49,476、val 10,999；旧数据报告的 `<1024` 为 49,416/10,977，差异来自边界约定，不是数据变化。

- 训练 14,432 图 / 448,469 实例，验证 2,584 图 / 73,421 实例；同场景有多个视角。
- **CAD model_id：train 114 种，val 20 种，交集为 0。** 这是新型号泛化任务，不能只靠记住训练元器件外观；分层抽样和置信区间应考虑 scene/model 相关性。
- 训练/验证小目标中，`header_connector` 分别为 1,857/5,352，`fpc_connector` 为 86/1,843。两者在 val small 中共占 **65.42%**，在 train small 中共占 **3.93%**。均匀按图采样不能自动纠正这种差异；也不能只过采样 86 个训练 FPC 小实例来声称解决新型号泛化。
- 验证小目标外接框等效边长中位数 **44.27 px**，**75.23%** 的框面积超过 32²；可见 mask 占外接框面积中位数 **35.19%**。约 **19.53%** 的长短边比大于 3。小面积经常对应细长、稀疏或遮挡后的可见区域，不能直接等同于极小方框。
- 训练小目标也有相同趋势：外接框等效边长中位数 41.64 px，可见填充率中位数 29.85%。因此 anchor 设计应基于 **bbox** 分布/覆盖率，不能基于 mask 面积整体下移尺度。
- 原有全量 mask 解码、面积、紧致框校验通过。本次查看 RGB/深度/GT 示例未发现明显整体错位，但未完成逐像素深度边缘对齐审查。

### 3.3 定位与掩码的分离诊断

对四组 `best_val_predictions.json`，以**同一批按 GT mask 面积定义的小目标**统计：score≥0.05、每图最多100个现有预测，是否存在达到 IoU 阈值的预测。

| 模型 | 存在 box IoU≥0.5 | 存在 mask IoU≥0.5 | 存在 mask IoU≥0.75 |
|---|---:|---:|---:|
| B0 | 71.37% | 58.11% | 33.92% |
| B1 | 71.43% | 57.61% | 33.82% |
| M1 | 79.71% | 63.14% | 35.39% |
| A1 | 79.77% | 63.36% | 35.48% |

这是**允许重复覆盖的诊断率，不是 COCO AP/AR，不是 RPN recall**。box 与 mask 的最优预测可能不同。M1 中有 2,136/10,999 个小目标存在 box IoU≥0.5，却不存在 mask IoU≥0.5，约19.42%。这使掩码形状/可见区域学习成为高优先级，同时仍需改进剩余定位失败。不能仅凭这些数值把所有失败都解释成边界误差，需局部图板确认。

不能直接拿官方 bbox APs 与 segm APs 相减当作掩码损失：两个评估可能使用不同面积口径。本次诊断专门固定同一 GT mask-small 集合。

### 3.4 深度链路与学习动态

当前实现逐图换算米、train p1/p99 归一化、同步几何变换、无效深度填中性值；有效性 mask 未输入网络。RGB 保留 Detectron2 的 0–255 减均值尺度，深度为约 [-2,2]，第四通道卷积由 RGB 权重均值初始化。

本次各取24张按排序均匀间隔图：RGB 通道标准差均值的中位数约48–49，归一化有效深度标准差中位数约0.22。**这提示需要检查两模态特征/梯度幅度，尚不能据输入标准差就断言深度支路失效。** 应补查 stem 分模态激活、梯度和有效深度边界；不直接把深度乘一个任意大常数。

曲线在约第7.5 epoch首次降学习率后明显改善。例如 A1 在108k/112k步的 APs 为25.62/27.30，B1为23.93/25.40。原 pilot 3,000图次只有0.208 epoch，不适合架构淘汰；短试验必须有完整的学习率下降阶段。10 epoch末是否需要延长，以新配方曲线判断。

## 4. 算法优化顺序

### P0：固定诊断和实验协议

使用已有权重/预测，补充按 mask 面积（1–64、65–256、257–1024）、bbox形状/填充率、型号、semantic_type、density、renderer 的错误分析。对小目标至少区分：框未覆盖、框覆盖而 mask 不足、相邻实例混淆、低置信度预测。为代表案例输出原分辨率局部 RGB、局部深度、GT、B0、B1、M1，不依赖缩小后的整图判断细针脚。

若需要改 RPN，另行用固定验证子集输出原始 proposals，计算 top-100/300/1000 的 small/mid/large proposal recall；当前最终预测不能充当 proposal recall。

### P1：适配跨型号与稀疏目标的数据配方

1. 采样依据来自 train：按 semantic_type/CAD model 做温和均衡，候选重复上限3；批次中保留自然分布样本，避免稀有型号过拟合。权重不用 val 频数拟合，val仅选择候选是否有效。
2. 加入保持标签正确的90°旋转、适度亮度/对比度扰动；RGB/depth/valid/GT 的几何必须同步，颜色变换仅施于 RGB。
3. 验证“原图与实例中心裁剪混合”：起点为50%原图、50%训练实例附近的512/768窗口放大到1024；控制裁切后的 mask/bbox，保留边缘截断标注，不能把仍可见的其他实例变成未标注前景。保留原图分支以免只学局部视野。单独检查小面积原因，避免大量放大1–4像素碎片制造噪声。
4. 裁剪实现前必须做叠图校验；当前 mapper 明确不支持 crop，不能只在 YAML 开关后视为已实现。先采样/增强，再单独加裁剪，记录其条件贡献。

此阶段先用RGB基线快速评估配方；最终四格消融都使用同一已选数据配方，避免把采样收益归给融合模块。输入分辨率起点仍为1024，不一开始切到1536或全图切片推理。

### P2：有效性引导的轻量深度残差融合

保留RGB预训练主干，另设小型深度编码器（少量3×3卷积+GroupNorm），输入有效深度、valid mask，以及候选的局部相对深度/梯度。先以相对深度+valid验证；梯度作为独立增量，不同时堆所有几何编码。

在P2/P3做受valid约束的残差融合：`F_fused = F_rgb + gate * projection(F_depth)`。末端投影零初始化，使初始网络保留RGB行为；门控使用近中性初始化。避免“gate和深度输出同时恒零”造成深度支路无梯度。无效像素邻域的深度梯度必须屏蔽，不能把空洞当物体边缘。增加小概率深度 dropout，让模型不依赖某些渲染深度捷径。

新分支单独归一化，不改变RGB预训练输入标度。对各级分模态激活/梯度做日志核验。深度边缘只是几何证据，不能直接拿深度不连续当完整实例标签，也不使用GT/support_rle生成推理输入。可先用四通道零初始化做低成本诊断，但主算法以浅层有效性门控为候选。

### P3：面向稀疏可见区域的 mask 监督与细化

第一候选保持标准 mask pool=14 和现有主干，在每个正ROI内做实例平均的 `BCE + 0.5*Dice`；检查原实现已如何平均ROI，不能重复宣称新增实例均衡。第二候选才增加窄边界带加权BCE，初始边界权重2、带宽1–2个ROI输出像素；对极小实例/边界占满ROI做权重上限，避免噪声主导。

Dice针对稀疏mask前景，边界项针对细结构，是待验证机制，不能承诺AP提升。若同一目标定位好而高IoU掩码仍不足，再做P2细特征驱动的不确定点细化（PointRend思路），先检查当前CoreX所需算子。按需细化优先于所有ROI都扩大到28；二者以同预算和含后处理速度比较。

不要强迫深度边缘和GT边界一致；不要用形态学闭运算一刀切填洞，连接器孔洞和针脚可能是真实结构。

### P4：anchors / proposals 作为诊断后的条件分支

起点恢复B0的标准proposal数与mask pool，先不沿用M1的全部高开销设置。根据train bbox尺寸/长宽比计算anchor覆盖率；候选可在P2保留32并补16，同时保留64/128/256/512的尺度覆盖。当前默认RPN共享head对各层anchor数量有要求，必须保持各层兼容或明确改head，不能只在P2加一个尺寸后忽略通道数不一致。

仅当proposal recall显示明显不足，才测试更宽长宽比或更多proposals；分别测精度与代价。小mask不等于小bbox，且P2已有步长4，把anchor改成8不等于新增高分辨率特征。

## 5. 四卡使用与快速验证

### 5.1 现有开销支持先改实验流程

- 当前通过既有 `./seg_project/run.sh ixsmi` 已正常检查：4张BI-V150，各32GiB，当前利用率0%，约68MiB占用，无列出的GPU进程。直接shell的ixsmi报错来自已有库路径差异；无需安装驱动。
- 上轮单卡训练日志 `max_mem`：B0/B1约3065/3069MiB，M1/A1约3732MiB。这是框架记录的峰值，不等于整卡占用；说明值得测每卡batch=2/4，**不能仅凭剩余显存推定吞吐提升**。
- B0循环14h49m，其中hooks6h04m；M1循环20h31m，其中hooks8h15m，均约40%。每组37次完整验证过密。hook含验证/保存，不能全部叫GPU训练时间。
- 若只加速M1训练部分、验证部分完全不变，即使前者理想4倍，仍约 `12.27/4+8.24=11.31h`。这是说明串行开销的理想化算式，不是新任务ETA；实际DDP验证可分发推理，但COCO汇总仍在主进程。

### 5.2 下一步实测，而非直接跑满一天

新训练阶段开始时，使用独立输出做短profiling，比较：单卡batch=1/2/4，四卡每卡batch=1/2；先20–50步预热，再计100–200步稳定时间，记录图/秒、step p50/p90、读取时间、峰值显存、CPU负载、DDP通信及一次分布式验证时间。必要时再测2卡。现有5步DDP smoke只证明可用，不证明加速。

同时区分两种比较：固定每卡batch的资源扩展效率；固定全局batch的优化可比性。优化实验必须固定全局batch、样本呈现数、学习率日程与随机种子。四卡数据并行不会自动把四张显存合成128GiB。

四卡batch=4时，3 epoch是10,824次更新，10 epoch是36,080次更新；batch=8则分别为5,412/18,040次。不能继续套144,320步。以batch=4先试LR=0.005/0.01的短稳定性检查，不能假定线性放大LR必优；选定后统一用于四格对照。

`tools/train.py` 已会按world size缩放batch、LR和日程，且`--stage`会重新设置MAX_ITER/STEPS。实施时核对最终resolved config，避免手工与入口重复缩放。保留FrozenBN，先不加SyncBN；AMP作为后续独立性能优化，需验证CoreX算子与数值，不能为此升级底层依赖。

### 5.3 选择四卡联合还是并行实验

**下一阶段优先四卡DDP逐项推进**：先验证新配方，再验证融合/掩码机制，及时结束明显无效方向。理由是实验决策有依赖，早拿到一个可靠结果比同时等待四个完整10 epoch更有价值。

若单卡实验耗时T、四卡加速S4，四个独立实验单卡并行约T，四卡串行约4T/S4（相同额外开销假设）。例如S4=2.5，四卡串行全部完成约1.6T，因此不能宣称它在独立实验总吞吐上必胜。

默认决策：实测S4达到约2.5且需要连续决策时用四卡；若通信/CPU瓶颈使收益低，则测2+2并行。两条已经定义清楚的独立消融适合2+2；最终选定配置及完整验证使用四卡。2.5是规划阈值，不是实测结果或硬性作业要求。不同拓扑比较时保持同全局batch，必要时明确梯度累积的实现与影响。

## 6. 实验矩阵、验证频率与验收

### 6.1 预算阶梯

1. CPU数据与已有预测诊断：本次已完成主要统计；还需代表错误图板、深度激活/梯度及必要proposal检查。
2. 训练配方筛选：2–3 epoch，统一初始权重；短日程必须完成降LR。先改采样/增强，再测试混合crop；短试验只筛方向，0.5点左右差异不直接判胜负。
3. 四格算法对照：候选先3 epoch，关键候选再10 epoch。都从同源COCO预训练独立启动，不能把一个训练10 epoch模型继续微调与另一个从头3 epoch模型做公平对照。
4. 胜出模型和匹配基线增加第二个seed；如末段仍稳定提升再延长到20 epoch。延长预算的收益独立报告，不归为模块贡献。

### 6.2 核心四格

以下四组使用同一已选数据配方、相同训练预算、batch、LR、分辨率和后处理。

| 编号 | RGB | 深度门控 | mask改进 | 作用 |
|---|---|---|---|---|
| N0 | 是 | 否 | 否 | 新配方RGB对照 |
| N1 | 是 | 是 | 否 | 验证RGB-D融合 |
| N2 | 是 | 否 | 是 | 验证小目标mask机制 |
| N3 | 是 | 是 | 是 | 最终RGB-D组合候选 |

`mask改进`采用P3中经短试验选择的最简有效版本，不能未经消融同时上Dice、边界、点细化后宣称各自有效。旧B0/B1/M1/A1作为历史基线保留；新旧配方不同的差异只能称系统改进。新的正式RGB-D候选不局限于旧最终选择脚本的B1/M1名称，实施阶段应版本化扩展候选政策及审计工具。

### 6.3 验证安排

- 建立固定约384图的快速val子集：按scene分组兼顾semantic_type、密度、面积和renderer，保存清单及计数；只做趋势诊断。不能使用当前`EVAL_LIMIT`的“排序前N张”，它会偏向早期型号/场景。
- 3 epoch筛选至少末尾做完整val；10 epoch正式试验建议第1/3/5/7/9/10 epoch完整验证，共6次。候选共享节点，重要学习率变化附近可预先加点；不根据某候选表现单独增加选模机会。
- checkpoint保存频率和验证频率分开；保留完整恢复状态。DDP分发推理，主进程汇总COCO；记录推理、RLE、COCO汇总、存盘的各自耗时，避免把子集分数写入正式best。
- 当前hook只能使用固定period、当前子集命名标记为smoke；实施时需明确支持独立快速验证和正式节点，防止未经实现就把本计划当可直接运行配置。

### 6.4 通过与停止标准

- 工程正确性：先做小批样本拟合、RGB/depth/valid/GT对齐、DDP参数一致性、无NaN与恢复检查。输入/损失重大改动后再训练全数据。
- 正式优选：RGB-D候选优先按完整val APs排序，同时整体AP至少达到匹配的RGB-D基线；报告相对N0及旧B0的代价。避免只为APs接受未经说明的整体AP下降。
- 项目目标（非成绩承诺）：相对匹配基线争取APs提高至少2点，整体AP不退；先把历史约28的APs推进到30以上作为方向目标。若相对基线仅有0.3–0.5点变化，补seed/场景bootstrap，不当成已确定提升。
- 效率目标：优先保留较匹配基线延迟增加不超过约20%的轻量改动；这是新轮预设工程偏好，不追溯否定旧实验。超过时明确报告精度/速度取舍，不能用阈值掩盖真实收益。
- 若深度分支在两档预算均没有收益，先查激活/梯度、归一化和深度消融，不直接继续20 epoch。若框覆盖改善但高IoU mask不改善，停止增加proposals，把预算转向mask监督/细化。
