## 1. 结论速览

1. **本数据集的“小目标”主要是被严重遮挡后剩下的残片，而不是本身尺寸小的元件。** 小目标的可见率代理（同图同型号实例中“本实例面积 / 最大面积”）中位数：train 0.08、val 0.25、test 0.08；train 86%、test 94% 的小目标可见率 < 25%。55–62% 的小目标 mask 由 ≥2 个不连通碎片组成，约 20% 有 ≥5 个碎片。小目标外接框等效边长中位数约 42 px，框内填充率中位数约 0.3。
2. **瓶颈在 mask，不在框。** 同一批 GT 小目标上，A1 的 bbox APs = 43.0，但 segm APs = 28.0。按碎片切片：单连通小目标 mask APs 45.1；2–3 碎片 15.2；≥4 碎片 **6.0**（同组 bbox APs 仍有 30.2）。
3. **打分排序也有明显空间。** 用每个预测与 GT 的真实 mask IoU 替换置信度（理想上界），A1 的 APs 从 28.0 → 33.6，AP 55.6 → 62.7。说明“mask 质量感知的打分”值得做。
4. **旧方案收益小的原因可以解释：**
   - 旧小目标改动（小 anchors、更多 proposals、28 pool）针对“框找不到”，但真正瓶颈是碎片化 mask。所以只换来约 +1.2 APs，却多花了约 56% 推理时间。
   - 旧深度早期融合存在**数值尺度问题**：RGB 输入为 0–255 减均值、std=1，约 ±128；深度为 `(d-0.5)/0.25`，约 ±2；第 4 通道权重取 RGB 权重均值。深度对 stem 的贡献只有 RGB 的约 1/60，实际上被忽略。B1/M1 比 B0/A1 低约 0.5 APs，属于这一实现下的结果，并不能说明深度没用。
   - 训练配方偏弱：单卡 batch=1、LR 0.0025、10 epoch。峰值显存仅 3.7 GB / 32 GB，输入分辨率、batch、模型容量都有很大余量。
5. **val 与 test 的小目标构成不同。** val 相机更远（相机高度中位数 0.85 m，train/test 约 0.80 m），小目标中“远处完整小件”比例更高、可见率更高；test 的小目标与 train 相近，主要是重度遮挡残片，而且极小碎片（≤256 px²）更多。推论：val APs 可能高估 test APs，对“多碎片 / 低可见率”切片的提升对最终成绩更关键。这也是用 test 辅助最终选择的理由：在 val 上接近的候选，在 test 上可能拉开差距。
6. 三个划分的 CAD 型号**两两不相交**（114/20/18 种）；val 与 test 都只含 13 种 semantic_type，均是 train 27 种的子集。这是“新型号泛化”任务，不能指望记住外观。

|---|---:|---:|
| B0 | 55.61 → 62.04 | 26.75 → 33.01 |
| A1 | 55.56 → 62.67 | 27.98 → 33.60 |

检测数量：A1/M1 在 2,584 张 val 中分别有 672/588 张图达到每图 100 个检测上限；GT ≥70 的 238 张密集图中，196 张触顶。COCOeval 的 maxDets=100 不可改变，因此密集图中前 100 的**排序质量**直接影响 APs。

**判断：**
- 旧 M1/A1 的小目标改动只提高了“单连通 / 可见率低”的检出，对 2+ 碎片完全无效（15.6 → 15.2）。
- 下一步的主攻点是：(a) 碎片化、被遮挡实例的 mask 预测；(b) mask 质量感知的打分；(c) 足够的输入分辨率与特征分辨率。
- 深度最有价值的用途是**区分遮挡者与被遮挡者**：遮挡者更近；被遮挡残片在空间上分散，但处于同一深度/平面。它应该在 mask 头内被直接使用，而不仅仅作为 stem 的第 4 个通道。

## 4. 总体路线

```
阶段0 推理侧零训练改进（已有权重）  ──►  固定新的后处理默认值
阶段1 新训练配方 N0（RGB，四卡DDP，高分辨率）
阶段2 核心算法模块（每项单独消融，基于 N0 配方）
        M-A 几何深度编码 + 零初始化门控融合（修复深度尺度问题）
        M-B 深度引导的高分辨率掩码细化头（主改进，面向小目标）
        M-C 遮挡感知双层掩码头（面向多碎片）
        M-D MaskIoU 打分头（面向排序）
阶段3 主干/检测器容量（R101 / RegNetY / Cascade）
阶段4 遮挡式 RGB-D Copy-Paste 增强（可选）
阶段5 最终 2x 训练 + TTA / 集成 + 提交
```

预期收益是基于文献和本次诊断的**估计**，不是承诺；每一项都必须在完整 val 上证明。

| 阶段 | 改动 | 估计 val APs 变化 | 速度代价 |
|---|---|---:|---|
| 0 | maskness 重打分、NMS 阈值、score 阈值、测试尺度、翻转 TTA | +0.5 ~ +2 | 小（TTA 另计） |
| 1 | DDP 大 batch、1024–1536 多尺度训练、1280+ 测试、旋转/翻转、类型均衡采样 | +2 ~ +4 | 推理分辨率上升约 1.5–2× |
| 2 | M-B 高分辨率 RGB-D 掩码细化头 | +1.5 ~ +4（重点在多碎片切片） | +10–20% |
| 2 | M-C 遮挡感知双层 mask | +0.5 ~ +2 | +5–10% |
| 2 | M-D MaskIoU 打分 | +0.5 ~ +1.5（上界 +5.6） | <5% |
| 2 | M-A 正确的深度融合 | 0 ~ +1.5（不确定，需验证） | +10–15% |
| 3 | 更强主干 / Cascade | +1 ~ +2 | +30–80% |
| 4 | 遮挡式 Copy-Paste | 0 ~ +2 | 0（仅训练） |

目标：val segm APs 从 28.0 提高到 **≥ 34**（争取 36+），整体 segm AP 不低于 N0；同时提供一个“精度版”和一个“速度版”配置。

### 4.2 关于“更换主干后 baseline 也变了，之前是不是白做了”

**不会白做，但更换主干确实意味着 baseline 要跟着重跑一次。** 关键在于“改进前后对比”必须**同主干、同配方、同预算**，只差我们加的模块：

- 如果改用 R101，就要同时跑“R101 + 原始 Mask R-CNN”（N0-R101）和“R101 + 我们的模块”，两者对比才算改进收益。旧的 R50 结果不能直接拿来减。这会多花一次完整训练，赶时间时不划算。
- 换主干带来的通常是对各类目标都差不多的 +1–2 AP，它不针对小目标，也不算作业要求的“小目标算法改进”。本数据的瓶颈是多碎片 mask（≥4 碎片 APs 只有 6），主要靠 mask 头和打分解决，与主干容量关系不大。
- 所以本计划**全程固定 R50**。报告中的对比链为：
  - **B0（旧 R50 基线）**：保留为“论文式基线 / 改进前”，用于展示整体进步，以及旧模型在 test 上的表现。
  - **B0 → N0**：训练配方的收益，单独报告为“训练策略改进”，不计作模型创新。
  - **N0 → N1 / N2 / N3 / N3+M-D**：算法模块的收益（同为 R50、同为新配方），这是报告里“小目标改进”的核心证据。
- 旧的 B1 / M1 / A1 也有价值：它们是现成的**负面 / 有限收益消融**，说明“小 anchors + 更多 proposals 只改善单连通目标，对多碎片无效”“深度第 4 通道在 1/60 尺度下没有作用”。这正是报告要求的“改进前后对比与原因分析”。数据管线、评估、DDP、benchmark、提交校验、错误分析工具也全部继续复用。
- 时间富余时可以加一行“扩展：最终模块迁移到 R101”，并同时跑 N0-R101，作为附加结果，不替代主对比。

## 5. 阶段 0：推理侧零训练改进（约 0.5 天，四卡并行推理）

使用已有 `outputs/1x_a1/best_segm_APs.pth`、`1x_m1`、`1x_b0` 权重，只改推理。扫描在**完整 val** 上进行，最终选中的 1–2 组设置再在 test 上确认。需要扩展 `rgbd_seg/inference.py` 与评估工具，增加以下开关：

| 编号 | 改动 | 取值 |
|---|---|---|
| P0.1 | maskness 重打分：`score = cls_score × mean(mask_prob[mask_prob>0.5])^α` | α ∈ {0, 0.5, 1} |
| P0.2 | 框 NMS 阈值（10–11% 的 small GT 与其他 GT 框 IoU>0.5，会被 NMS 0.5 误抑制） | 0.5 / 0.6 / 0.7 |
| P0.3 | mask-NMS：先保留 300 个候选并全部预测 mask，再按 mask IoU 做 NMS，取前 100 | 阈值 0.5 / 0.6 |
| P0.4 | SCORE_THRESH_TEST | 0.05 / 0.01 |
| P0.5 | 测试尺度（训练为 896–1024） | 1024 / 1152 / 1280 |
| P0.6 | mask 二值化阈值 | 0.4 / 0.5 |
| P0.7 | 水平翻转 TTA（mask 概率平均） | 开 / 关 |

产出：一张“后处理 × 模型”表，固定阶段 1 以后的默认后处理（TTA 单独报告，不进入默认值）。P0.1 的效果也会给阶段 2 M-D 提供基线：如果 maskness 已经拿到大部分收益，M-D 的优先级下调。

## 6. 阶段 1：新训练配方 N0（RGB）

先修配方再加模块，避免把配方收益错误地归给模块。赶时间主线（4.1）中，N0 与所有消融用 **8 epoch**（14,432 iter，降 LR 点在 75% / 92%），最终模型用 16 epoch；下表中的 12 epoch 是完整版的设置。

| 项 | 旧（B0） | 新（N0） |
|---|---|---|
| 并行 | 单卡 | 四卡 DDP（已有 `ddp_smoke` 通过） |
| batch / LR | 1 / 0.0025 | 每卡 2 → 全局 8，LR 0.01（短测 0.01 / 0.02 稳定性） |
| 训练长度 | 10 epoch | 12 epoch = 21,648 iter（全局 8），在 75% / 92% 处降 LR |
| 训练尺度 | 短边 896/1024 | 短边从 1024–1536 随机，长边 ≤1536 |
| 测试尺度 | 1024 | 1280 起步（阶段 0 的结果决定）；同时报告 1024 速度版 |
| 几何增强 | 水平翻转 | 水平 + 垂直翻转、90° 旋转（RGB/深度/mask 同步） |
| 光照增强 | 无 | 亮度/对比度/饱和度轻度扰动（仅 RGB） |
| 采样 | 均匀 | 按 semantic_type 训练集频率的图像级 repeat factor（上限 3，权重只用 train 计算） |
| mask 头 | pool 14 → 28 | 保持 14 → 28（M-B 再改） |
| anchors / proposals | 默认 | 默认；只有 proposal recall 证据显示需要时才改 |
| ROI 采样 | 512 / 图 | 512 / 图；POSITIVE_FRACTION 0.25 → 0.33（每图 30+ 实例，正样本常被截断） |
| 后处理 | NMS 0.5 | 采用阶段 0 结论 |
| AMP | 关 | 先在 CoreX 上做 200 iter 数值 smoke，稳定再开；不稳定就保持 FP32 |
| 验证 | 每 4k iter 全量（37 次，约 40% 时间） | 每 2 epoch 一次完整 val，DDP 分片推理；再加一个 400 图分层子集用于看趋势 |

吞吐需要先实测：比较单卡 batch 1/2/4、四卡每卡 batch 1/2，各 200 iter。按上轮 0.30 s/图估算，高分辨率四卡约 8–12 图/s，12 epoch 约 4–6 小时（含验证）。

N0 同时作为阶段 2 所有模块的公共基线。

## 7. 阶段 2：核心算法模块

所有模块都写成 Detectron2 可注册组件，放在 `rgbd_seg/modeling/` 下，通过 YAML 开关，彼此可独立消融。

### M-A 几何深度编码 + 零初始化门控融合（RGB-D 融合，修复旧实现）

**输入编码**（只依赖深度图与固定 K，train/val/test 一致）：
1. 用固定 K 将深度反投影为点云；对每张图 RANSAC 拟合桌面平面，得到每像素**离桌面高度** h（对相机距离不敏感，可缓解 val 相机更远的偏移）。
2. 由点云计算**表面法向**（3 通道）。
3. **深度不连续强度**：相邻像素深度差 / 深度，用来表示遮挡边界。
4. 无效深度：各通道置 0，并额外提供 valid 通道。

每个通道按训练集统计标准化，然后缩放到与 RGB 预处理后**相同的数值量级**（std 约 50），不再出现 1/60 的问题。

**融合**：双流结构。RGB 主干保持 COCO 预训练；深度分支是轻量的 ResNet-18 风格编码器（或复制 R50 stem+res2 并用 RGB 权重初始化），在 res2–res5 每级通过 `F_rgb + σ(g) ⊙ Conv1×1(F_depth)` 融合。Conv1×1 零初始化，所以训练起点与 RGB 模型完全相同，不会损伤 RGB 性能；门控 g 由两路特征共同预测。训练时以 p=0.2 随机丢弃深度，防止过度依赖。日志记录各级两路特征范数与梯度范数，直接验证深度确实被使用。

**消融**：N0 vs N0+M-A；M-A 中“几何编码 vs 原始深度”、“门控融合 vs 早期融合（修正尺度后）”。

### M-B 深度引导的高分辨率掩码细化头（主改进，面向小目标）

动机：小目标框约 42 px，在 P2（stride 4）上只有约 10×10 个有效特征；碎片与细丝（内切半径 ≤2 px 占 7–12%）在特征层已经丢失。深度的不连续与“与目标同一深度”的信息能直接区分哪些像素属于被遮挡残片。

结构：
1. 标准 mask 头输出 28×28 粗 mask logits。
2. 细节分支：对每个 ROI，从**原分辨率输入**（RGB + M-A 的几何通道）和 P2 特征上 ROIAlign 到 56×56。深度通道再做 ROI 内相对化：减去粗 mask 前景内深度的中位数，得到“与本实例同深度”的线索。
3. 输入为 4 层 3×3 卷积（64 通道），与上采样后的粗 logits、P2 特征拼接，输出 56×56 mask。
4. 损失：56×56 上 BCE + 0.5×Dice（Dice 缓解稀疏前景，碎片目标的前景占比约 0.3）。可选：窄边界带（1–2 像素）权重 2。
5. 推理时只对最终的 ≤100 个检测运行，代价可控。

对照：PointRend（官方实现在 `detectron2/projects/PointRend`，需要 COCO 预训练权重，见第 10 节），作为“通用细化”对比，证明深度引导的必要性；消融“细节分支去掉深度通道”“只用 RGB 原图”“只用 P2 特征”。

这是报告中“针对小目标 + RGB-D 融合”的主创新点。验收看 small 整体、2–3 碎片、≥4 碎片切片的 APs。

### M-C 遮挡感知双层掩码头（面向多碎片）

参考 BCNet（Ke et al., CVPR 2021）。在 ROI 内同时预测：
- 遮挡者 mask：ROI 内其他 GT 实例与本 ROI 重叠部分的并集。训练标签由 train GT 直接构造；可用深度把“更近者”定义为遮挡者，使标签更准确。
- 被遮挡者（目标）mask：输入中拼接遮挡者分支的特征/预测。

目的：让网络显式学习“框内哪些像素属于前面的元件”，从而输出不连通但正确的残片。可与 M-B 组合（M-C 生成粗 mask，M-B 再细化）。

### M-D MaskIoU 打分头（面向排序）

参考 Mask Scoring R-CNN：用 ROI 特征与预测 mask 回归 mask IoU，最终 `score = cls × maskIoU`。上界分析显示理想打分可提升 APs 5.6；文献中实际可得约 1–1.5 AP。如果阶段 0 的 maskness 已经拿到大部分收益，就降级为可选项。

### 阶段 2 实验矩阵

全部基于 N0 配方，同 seed、同预算。筛选用 6 epoch（含降 LR），候选再跑完整 12 epoch。

| 编号 | 深度 | M-B | M-C | M-D | 作用 |
|---|---|---|---|---|---|
| N0 | – | – | – | – | 新配方 RGB 基线 |
| N1 | M-A | – | – | – | 深度融合本身的收益 |
| N2 | – | ✓（无深度通道） | – | – | 高分辨率细化本身 |
| N3 | M-A | ✓ | – | – | 主模型：RGB-D 细化 |
| N4 | M-A | ✓ | ✓ | – | + 遮挡建模 |
| N5 | M-A | ✓ | ✓ | ✓ | 完整模型 |
| N3-PR | M-A | PointRend 替代 M-B | – | – | 对照 |

报告所需的“改进前后对比”由 N0→N1→N3→N5 和对应消融组成；旧 B0/B1/M1/A1 作为历史基线保留。

## 8. 阶段 3–5

**阶段 3 容量**（需要上传权重）：把阶段 2 最优组合迁移到 R101-FPN、RegNetY-4GF（LSJ 400ep COCO 权重）、Cascade Mask R-CNN R50 上，各跑 12 epoch。选择标准：APs 提升 ≥0.8，且速度可接受。

**阶段 4 遮挡式 RGB-D Copy-Paste**（可选，在阶段 2 有结论后做）：从其他训练图中复制实例（RGB、深度、mask），放到目标图中随机位置的局部表面上，深度按“源实例离桌面高度 + 目标位置桌面深度”合成。被覆盖的原实例 mask 相应扣除，剩余面积 <10 px 的实例删除。这样能人工生成大量“重度遮挡残片”，与 test 小目标形态一致（这一判断来自 train 统计，train 本身也是 86% 低可见率）。概率 0.3，粘贴 1–5 个实例。

**阶段 5 最终模型**：
- 选定配置从 COCO 预训练重新训练 24 epoch（2x），四卡 DDP。
- 补第二个 seed 给最终模型与 N0，报告均值；或用场景级 bootstrap 给出 APs 的置信区间。
- TTA：水平翻转 + 2 个尺度，mask 概率平均；可选 2 模型集成。TTA/集成必须计入推理时间，并与单模型结果分开报告。
- 交付两个版本：精度版（最高 APs，含 TTA）和速度版（1024 输入，无 TTA）。

**备选路线（GPU 空闲时）**：Mask2Former（R50 / Swin-T，200 queries，1280 输入）。它无 NMS、天然适合不连通 mask，但对小目标较弱，而且 MSDeformAttn 在 CoreX 上需要纯 PyTorch 回退或重新编译。需要先做 1 天 go/no-go：算子可用、单卡吞吐、3 epoch val APs 是否接近 N0；不达标就放弃。需要上传 Mask2Former 源码与权重。

## 9. 实验协议与四卡调度

- **主指标**：完整 val（2,584 张）的 segm/APs。同时报告 AP/AP50/AP75/APm/APl、bbox 指标、参数量、模型大小、1024 与实际测试尺度下的单卡速度。
- **诊断切片**：每个实验都运行 `pred_slices.py`，固定输出碎片数、可见率、密度、相机距离、类型切片和理想打分上界。
- **选择规则**：
  1. 超参和后处理扫描只在 val 上做，按完整 val APs 排序；整体 AP 不得低于 N0 超过 0.3。
  2. 从 val 排名前 2–4 的候选中，按 **test segm APs** 选最终模型 / checkpoint / TTA 设置（整体 test AP 不得明显下降）。
  3. val 与 test 结论冲突时，以 test 为准，但要在报告中写明两者的数值。
  4. 报告中注明“最终选择使用了 test 指标”，并同时给出 val 结果。
- **test 评估**：test 共 2,112 张、75,462 个实例。生成 `datasets/blender/annotations/instances_test.json`（只用于评估，不注册为训练集），评估命令与 val 相同；每个候选的预测保存在 `outputs/<实验>/test_predictions.json`。
- **快速子集**：从 val 按场景分层抽 400 张（覆盖 density/composition/type），只看趋势，不写入 best。
- **四卡用法**：
  - 阶段 0：四卡各跑一组推理。
  - 阶段 1、3、5：四卡 DDP 单实验。
  - 阶段 2 筛选：两组 2 卡 DDP 并行（每组全局 batch 8 = 每卡 4；显存足够），或四卡串行，按实测加速比决定。
- **时间估计**：完整版约 8–10 天；当前执行 4.1 的赶时间主线，约 4 天（需按实测吞吐修正）。

## 13. 与旧计划的主要区别

| 方面 | 旧计划（10-16 / 10-18） | 本计划 |
|---|---|---|
| 对“小目标”的理解 | 小尺寸框 → 改小 anchors | 遮挡残片、多碎片、低可见率 → 改 mask 与打分 |
| 深度 | 第 4 通道早期融合（数值尺度约 1/60，被忽略） | 几何编码 + 零初始化门控双流；在 mask 头内按 ROI 使用相对深度 |
| 训练配方 | 单卡 batch 1、1024、10 epoch | 四卡 DDP、batch 8、1024–1536 多尺度、更多增强、类型均衡 |
| 后处理 | 固定 NMS 0.5、score 0.05 | maskness / MaskIoU 重打分、NMS / mask-NMS 扫描、测试尺度 |
| 验证开销 | 37 次完整验证，约占 40% 时间 | 每 2 epoch 一次 + 分层子集 |
| 结构 | 只有 Mask R-CNN 超参改动 | 新增细化头、双层遮挡头、IoU 头，可选更强主干、Cascade、Mask2Former |
